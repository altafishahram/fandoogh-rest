# ترجمه خودکار AdminCafe

در نسخه ۱.۲.۰، فارسی متن اصلی ووکامرس است. ماژول اختیاری ترجمه، عنوان و توضیحات غذا و تنوع‌های موجود، نام دسته و متن نمایشی رستوران را به زبان‌های فعال انگلیسی، چینی ساده‌شده و ترکی تبدیل و در همان سایت ذخیره می‌کند. متن‌های ثابت رابط از قبل ترجمه شده‌اند.

## راه‌اندازی

1. در حساب Google Cloud خود یک پروژه آماده کنید، صورتحساب را فعال و Cloud Translation API را برای پروژه فعال کنید. قابلیت دسترسی حساب و ارتباط HTTPS هاست با سرویس باید برقرار باشد. افزونه از Cloud Translation **Basic v2 / NMT** استفاده می‌کند.
2. یک API key بسازید. در محدودیت API، دسترسی را به Cloud Translation API محدود کنید. برای این ارتباط سمت سرور، در صورت ثابت بودن IP خروجی هاست، محدودیت IP سرور را نیز تنظیم کنید؛ محدودیت HTTP referrer مرورگر برای این اتصال مناسب نیست.
3. در پنل اختصاصی، «تنظیمات ← ترجمه خودکار» را باز کنید و کلید را در کادر رمز وارد و تنظیمات ترجمه را ذخیره کنید. کلید را در چت، فایل سورس یا محتوای برگه قرار ندهید.
4. ترجمه خودکار را فعال کنید. زبان‌های مقصد از زبان‌های فعال منوی مشتری گرفته می‌شوند؛ فارسی زبان مبدأ است.
5. یک غذای فارسی را ذخیره کنید. صف در پس‌زمینه اجرا می‌شود؛ برای غذاهای قبلی، «ترجمه موارد موجود» را بزنید. وضعیت و خطاهای قابل پیگیری در همین بخش هستند.

تنظیمات این بخش جداگانه ذخیره می‌شود؛ دکمه ذخیره ظاهر و تنظیمات عمومی جای ذخیره اتصال ترجمه را نمی‌گیرد. تا آماده شدن ترجمه، متن فارسی یا ترجمه قبلی نمایش داده می‌شود.

روش جایگزین برای مدیر فنی سایت، تعریف `ADMINCAFE_GOOGLE_TRANSLATE_API_KEY` در پیکربندی خصوصی وردپرس است. در این حالت کلید از سرور خوانده می‌شود و پنل مقدار آن را نمایش نمی‌دهد. کلید واقعی را وارد مخزن کد نکنید.

## مصرف و هزینه

فقط متن نمایشی موردنیاز به سرویس ارسال می‌شود: نام، توضیحات غذا، نام دسته و متن رستوران. قیمت، موجودی، SKU، تصویر و اطلاعات مشتری و سفارش ارسال نمی‌شوند. ترجمه‌ها در metadata ووکامرس و تنظیمات سایت ذخیره می‌شوند؛ باز شدن منو و تغییر زبان مشتری به سرویس ترجمه درخواست نمی‌زند.

مصرف بر اساس تعداد کاراکترهای ارسال‌شده برای هر زبان مقصد است. برای نمونه، اگر متن تازه ۱۰۰۰ کاراکتر باشد و هر سه زبان مقصد فعال باشند، حدود ۳۰۰۰ کاراکتر ورودی ترجمه مصرف می‌شود. تغییر صرفاً قیمت یا موجودی ترجمه تازه نمی‌خواهد. درخواست ناموفق ممکن است مصرف رزروشده افزونه را افزایش دهد؛ شمارنده محلی، صورتحساب گوگل نیست.

سقف کاراکتر روزانه افزونه را متناسب با منو تعیین کنید و سهمیه‌ها و هشدارهای صورتحساب پروژه گوگل را هم تنظیم کنید. روز شمارنده بر اساس UTC عوض می‌شود. سقف افزونه فقط درخواست‌های همین سایت را محدود می‌کند؛ مصرف کلید در برنامه‌های دیگر را کنترل نمی‌کند. برای نرخ و اعتبارهای فعلی، [قیمت رسمی سرویس](https://cloud.google.com/products/translate/pricing) را بررسی کنید.

## اصلاح دستی و تغییر متن فارسی

ترجمه‌های موجودی که مدیر دستی نوشته است حفظ می‌شوند. اگر مدیر خروجی خودکار یک فیلد را اصلاح یا عمداً خالی کند، آن فیلد برای همان زبان محافظت می‌شود؛ تغییر بعدی فارسی، اصلاح مدیر را بازنویسی نمی‌کند. فیلدهای خودکار دیگر با متن فارسی تازه به‌روزرسانی می‌شوند. برای نام‌های خاص غذا و اصطلاحات برند، از همین اصلاح دستی استفاده کنید.

اجرای صف، محصول، دسته یا سفارش جدیدی نمی‌سازد و مبلغ، موجودی و زبان پنل را تغییر نمی‌دهد. ترجمه نمایش داده‌شده در رسید سفارش‌های قبلی طبق snapshot زمان ثبت باقی می‌ماند.

## اجرا، خطا و نگهداری

صف از Action Scheduler ووکامرس و در صورت نبود آن از WP-Cron استفاده می‌کند. هاست باید اجرای منظم صف/cron داشته باشد؛ روی سایت کم‌ترافیک، cron واقعی هاست را تنظیم کنید. ذخیره غذا منتظر پاسخ شبکه نمی‌ماند. هنگام قطعی سرویس یا رسیدن به سهمیه، منو با محتوای موجود کار می‌کند و مدیر می‌تواند وضعیت را بررسی و خطاها را دوباره امتحان کند.

کلید واردشده در پنل به‌صورت رمزگذاری‌شده و خارج از تنظیمات عمومی نگهداری می‌شود. رمزگذاری به کلیدهای خصوصی WordPress وابسته است؛ پس از تغییر salts یا انتقال سایت با salts متفاوت، ممکن است نیاز باشد API key را دوباره وارد کنید. در پاسخ REST پنل فقط وضعیت تنظیم بودن کلید برمی‌گردد؛ مقدار، بخش پایانی یا متن خام خطای سرویس نمایش داده نمی‌شود.

خاموش کردن ترجمه خودکار، ترجمه‌های ذخیره‌شده را حذف نمی‌کند. برای قطع اتصال، کلید ذخیره‌شده را از تنظیمات ترجمه حذف کنید؛ اگر کلید از constant خوانده می‌شود، تغییر آن باید در پیکربندی سرور انجام شود. پشتیبان‌گیری از پایگاه داده و تنظیمات خصوصی سرور را طبق روال سایت نگه دارید.

نسخه محلی با پاسخ ساختگی سرویس آزمایش شده است؛ آزمون اتصال واقعی فقط پس از پیکربندی کلید معتبر و دسترسی هاست انجام می‌شود. کیفیت نام‌های خاص و توصیف غذاها باید در زبان مقصد بازبینی شود.
